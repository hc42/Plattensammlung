# 0022. Installable app (PWA)

- **Status:** Accepted
- **Date:** 2026-10-23

## Context

On the phone the app is mostly used in record shops: scan a barcode, see "have it" or "on the
wishlist". Opening a browser and finding the bookmark each time is slow. Installed as an app it
starts from the home screen, without the browser's address bar, and the scan button is one tap
away.

## Decision

- **Web app manifest** at `/manifest.webmanifest`, generated by `ManifestController` instead of
  a static file: `start_url`, `scope` and the icon paths go through `~p`, so they carry the
  optional path prefix (ADR 0018), and name/shortcuts follow the browser language (ADR 0021).
  The route is public (browsers fetch manifests without cookies); it contains nothing private.
- **Icons:** `priv/static/images/icon.svg` (record on anthracite, the record inside the central
  safe zone so the same image serves as "maskable"), rendered to `icon-192.png`, `icon-512.png`
  and `apple-touch-icon.png` with `rsvg-convert`.
- **Shortcuts:** "Scan a barcode" (`/import?scan=1`, starts the camera) and the wishlist.
- **Service worker** (`priv/static/sw.js`, served from the app root so its scope covers the whole
  app): it only answers failed page loads with `offline.html`. It caches nothing else, so no
  private data or stale LiveView pages stay in the browser, and with network everything behaves
  as without it.
- `theme-color` per colour scheme and `viewport-fit=cover`, so the bottom tab bar keeps clear of
  the home indicator in standalone mode.

## Alternatives considered

- **Offline copy of collection and wishlist** (cache data in the service worker or IndexedDB,
  sync on reconnect): useful in shops without reception, but much more work (what is cached,
  for whom, how long; signing out must clear it). Can follow later on top of this.
- **Static manifest file:** simpler, but would break under a path prefix and can't be translated.
- **No service worker:** Chrome no longer requires one for installation, but without it an
  installed app shows the browser's error page when offline.

## Consequences

- The icons are generated files: after changing `icon.svg`, render the PNGs again
  (`rsvg-convert -w 512 -h 512 icon.svg -o icon-512.png`, likewise 192 and 180).
- A changed `sw.js` reaches users on their next visit (browsers check it on navigation);
  `skipWaiting` activates it right away. A new offline page needs a new cache name in `sw.js`.
- The CSP needs no change: manifest, worker and icons come from the app itself.
